## 決めたこと
- **APIは使わない**。GCPのサービスアカウントが要るため（外部サービスはユーザーが作る方針）。
  画面からのCSVエクスポートを読む形にした。月1回のダウンロードだけで回る。足りなければ後でAPIに上げる。
- **記事に載せるのは率だけ**。クリック数・表示回数の実数は出さない（匿名運営でPVを晒さない）。
  順位帯別CTR・表示シェア・型別の比較はすべて率なので、実数を伏せたまま記事になる。
- ページ別集計は `/articles/<id>` から frontmatter と結合する。
  独自記事と要約記事のどちらが読まれているかが出るので、2本立て自体の効果検証がこの表でできる。

## 注意
- `data/` はgitignore。Search Consoleの生データをリポジトリに入れない。
- CSVのファイル名・列名はSearch ConsoleのUI言語で変わる。スクリプトは日英どちらも読むが、
  他の言語で使うなら `FILES` / `COLUMNS` に足す。

## 書き方の基準（2026-09-04 追記。webpita.com の Labo を参考にした）
株式会社リタの WebPita Labo（https://www.webpita.com/labo/webPitaLabo_list.html）は、自社ログの観測だけで記事を出し続けていて、
「観測事実を中心に掲載し、推測や断定的解釈は記載しない」と方針を明示している。独自記事の型として取り入れる。
- **タイトルは結果そのもの**にする（例: 「Claude-Userは常に同じIPからだった」「GPTBotとOAI-SearchBotでは巡回パターンが異なる」）。
  「〜を調べてみた」「〜の分析」のような過程のタイトルにしない。
- **取得条件を本文の冒頭に書く**: 期間・対象（どのログ／どのプロパティ）・除外したもの（Bot・自分のアクセス・偽装UA）。
- **観測と解釈を段落で分ける**。観測から言えない一般化（「AIは〜する」）は書かない。書くなら「当サイトでは」を付ける。
- **AIクローラーの数は公式IP一覧と照合してから**数える（UAだけで数えると偽装分で多く出る。一覧は `src/lib/crawlers.ts` の `ipList`）。
- 実数は出さず率と傾向だけ（既存方針）。
- この基準は `/about` の「記事の作り方と編集方針」にも1段落で書いた。
