# 進捗: ChatGPTの会話ログでブランド推薦を実測する

ChatGPT（Web）の会話ログを取得し、**どのブランドが候補に入り、どう選ばれるか**を実測する。
ログには `web.run` に投げた検索クエリがそのまま残っているため、「なぜ選んだか」を本人に聞かずに
候補生成の過程が観測できる。独自記事（`original: true`）の材料。

## 計測条件

- ログイン状態、デスクトップWeb
- メモリ：無効（設定 → パーソナライズ → メモリを有効にする → OFF）
- カスタム指示：全項目を空
- 新規チャット。一時チャットは使わない（履歴に残らず取得できないため）
- 会話APIのレスポンスJSONを1会話1ファイルで保存
- モデル：`gpt-5-6`（全実行で一致）

## 実施済み（すべて 2026-09-05）

| セット | 時刻(JST) | 条件 | 完走 |
|---|---|---|---|
| 1 | 22:32〜22:36 | メモリON・カスタム指示ON | 5件中2件のみ |
| 2 | 22:47 | 両方OFF（A1のみ） | 1件 |
| 3 | 23:18〜23:22 | 両方OFF | **5件すべて** |
| 参考 | 22:5x頃 | ログアウト（シークレット）×2 | 回答のみ取得 |

プローブ5本：

- **A1** `SEO対策のツールでおすすめを教えて`（無条件・成熟カテゴリ）
- **G1** `AI検索対策（GEO）のツールでおすすめを教えて`（無条件・新カテゴリ）
- **B1** `個人ブログでも使えるSEOツールのおすすめは？`（+1条件）
- **B2** `月1万円以内・日本語対応・個人事業主向けのSEOツールを3つ挙げて`（+3条件）
- **C1** `2026年時点で最新のSEOツールのおすすめは？`（検索誘発語）

**最大の制約：全実行が同日 22:32〜23:22 の50分以内。反復としては1時点分しかない。**
「Don't Measure Once」（arXiv:2604.07585）の通り、日をまたいだ反復がないと揺れと差が分離できない。

## わかったこと

### 確度A：3回とも再現した

**1. 候補ブランドは検索する前に確定している**

ユーザーは一度もブランド名を出していないのに、`web.run` に投げる最初のクエリに製品名が入る。

```

22:47 (OFF)    : best SEO tools Ahrefs Semrush Google Search Console Screaming Frog ...
23:18 (OFF)    : SEO tools Ahrefs Semrush Google Search Console Screaming Frog ...
```

続けて `site:ahrefs.com` `site:semrush.com` 等で公式ページへ直行する。
**検索は候補を探すためではなく、記憶から出した候補を裏取りするために使われている。**
セット3では5プローブ中4本で、1本目のクエリにブランド名が入っていた。

**2. 条件を足すと候補が総入れ替えになる**

| プローブ | 1本目のクエリに出た候補 |
|---|---|
| 無条件（A1） | Ahrefs / Semrush / GSC / Screaming Frog |
| +個人ブログ（B1） | GSC / Ahrefs Webmaster Tools / Ubersuggest / ラッコキーワード / Google Trends |
| +月1万円・日本語・個人事業主（B2） | ミエルカ / Rank Tracker / Nobilista / ラッコキーワード（→GMO） |

条件1つで Semrush と Screaming Frog が落ち、**無料枠のある製品**に入れ替わる。
条件3つで**海外大手が全滅**し、国産だけになる。引用先も連動して全部日本のドメインになった。
3回とも同じ挙動だった。今のところこれが一番強い。

### 確度B：2回再現した

**3. 新しいカテゴリでは探索クエリが1本先に来る**

A1（SEO）は1本目のクエリ自体にブランド名が入るのに対し、G1（GEO）は1本目が
`best GEO generative engine optimization tools AI search visibility 2026` という
ブランド名なしの探索クエリで、名指しは2本目（Profound / Peec / Otterly / AthenaHQ）。
2回ともこの形だった。

ただし1本目と2本目は**同じバッチ**で送られており、検索結果は返ってきていない。
「まとめ記事を見てから候補を作る」というメカニズムではない（後述の訂正）。

**4. コアは動かず、周辺と順序が揺れる**

C1の1本目の候補は、1回目が「4強＋ラッコキーワード」、2回目が「4強＋**Surfer SEO**」。
G1の候補も Profound / Peec / Otterly は2回とも入り、5番目以降が入れ替わった
（HubSpot・ミエルカ・CINC → AthenaHQ。**2回目は日本語系が消えた**）。

A1の回答内の推薦順は、ログイン3回では GSC → Ahrefs → Semrush → Screaming Frog → GA で一致したが、
ログアウト2回では順序が入れ替わり Ubersuggest が増えた。

### 確度C：別条件で1回ずつ観測（記事には使えない）

- **カスタム指示は提示の仕方だけを変えた。** ON時は「僕なら Ahrefs にします」と1つに断定しASCII図を出す。
  OFF時は3つ提示して逆質問で終わる。候補5つと順序は同一だった。n=1対n=1。
- **ログアウトでも候補は同じだった。** ただしログアウト時のモデルは特定できない。

  `Semrush → company / "SEO and marketing platform"` のように、ブランドの分類と説明文が付く。
  ログインのJSONには存在しない。**誰が生成した文字列かは不明**（モデルか、後付けの注釈システムか）。
  ブランドエンティティ（レッスン13）の材料になりうるが、出どころを確定しないと主張を誤る。

| 当初の読み | 現在 |
|---|---|
| 引用は公式ドメインのみ | **崩れた。** 3回連続で公式のみだったが、セット3でC1が newstandard.digital、G1が sitepoint.com・byalkali.com を引用。正しくは「公式が多数だが、まとめ記事も混ざる」 |
| 推薦順も安定している | **崩れた。** ログイン3回はたまたま一致していただけ。ログアウト2回で順序が入れ替わった |
| GEOはまとめ記事を見てから候補を作る（2段階） | **支持されず。** 探索クエリと名指しクエリが同一バッチで、検索結果を見る前に候補が出ている |
| `memory_scope` の値でメモリ状態を検証できる | **誤り。** UIでOFFにしても `global_enabled` のまま。判定は `model_editable_context` メッセージの有無 |

## 手法上の知見

- **メモリの状態**：`memory_scope` / `is_do_not_remember` は当てにならない。
  `content_type: "model_editable_context"` のメッセージが**存在しなければOFF**。
- **カスタム指示**：ログに一切残らない。実行時に手で記録するしかない。
- **完走の判定**：最後のメッセージが `status: "finished_successfully"` かつ `content.parts[0]` が空でないこと。
  未完走だと `in_progress` で本文が空になる。画面上で「情報源」ボタンが出てから取得する。
- **ログの形式が2種類**：`messages` 配列のものと `mapping`（ツリー）のものが混在する。パーサは両対応が必要。
- **ログアウト時**：会話が保存されないので後から取得できない。モバイルWebの描画HTMLには
  最終回答・引用・エンティティ注釈は入るが、**`web.run` のクエリと検索結果は入らない**。
  候補生成を見たいならログイン一択。
- **ファイルがプロンプト名で保存されており、実行のたびに上書きされている。**
  セット1・2のログは既に失われ、この会話の中にしか残っていない。
  `A1_20260906_r1.json` のような命名に変え、プロンプト文はCSV側に持たせる。

## 引用と紹介文の分析（セット3・5件）

### 引用は2層構造

`grouped_webpages` の中身は「主」と `supporting_websites`（従）に分かれ、性質が完全に違う。

| | 件数 | 検索結果でのスニペット |
|---|---|---|
| 主引用 | 24 | **24件すべて空** |
| 従引用 | 20 | 19件が有り |

主引用のURLは全件「検索結果にURLはあるがスニペットが空」。従引用はスニペット付き。

### 紹介文の各要素の出どころ

| 要素 | 出どころ | 根拠 |
|---|---|---|
| ブランドの性格づけ | h1 / h2 / ファーストビュー（＝スニペット） | GMO「知識がなくても使える」→「SEOの知識があまりない個人事業主なら」 |
| 数値・仕様 | **主引用先のページ本文** | `group.gmo/news/article/9824/` に「単月契約：3,840円（税抜）/月」「月額2,992円相当」が完全一致で存在 |
| 税込換算などの派生値 | **モデルの計算** | 「税込4,224円」は出典に無い。3,840×1.1 の計算値 |

数値がスニペットに存在せず主引用先の本文にだけあることを実測で確認した。
「第三者サイトから拾って引用だけ公式に付け替えた」ではなく、**本文を読んでいる**。

### `snippet` フィールドの正体（288件）

**ChatGPTの `web.run` が返す `snippet` は、GoogleのSERPスニペットとは別物。**

- **クエリ非依存**：複数プローブに登場した15URLで、スニペットの完全一致 15/15、相違 0
- **固定長**：288件すべて 200〜206字（min 200 / 中央 202 / max 206）、**100%が末尾で切断**
- **meta description ではない**：照合した6ページすべてで meta の文言がスニペットに含まれない
  - 決定的な反証：Screaming Frog は meta が "Windows, macOS and **Ubuntu**"、本文が "**Linux**"。
    スニペットは **Linux** 側と一致した
- **レンダリング済みのページ本文**：Image:のalt 17%、`*`のナビリスト 19%、`[Input]`等のUI要素 14%、
  連続大文字（見出しの痕跡）78%
- title とは別フィールド。スニペット先頭と title の一致は 13% のみ

### 訂正：スニペットは「ページ先頭200字」ではなく「本文の先頭200字」

当初「レンダリング後テキストの先頭200字」と書いたが、**誤り**。実際のページを取得して
スニペットの冒頭24字が生テキストの何文字目から始まるかを測ったところ：

- **先頭（0〜5字目）から始まっていたもの 0件 / 冒頭が捨てられていたもの 12件**
- 捨てられていたのは `Skip to content`、グローバルナビ、ブラウザ警告・キャンペーンのバナー
- 除去量は ja.semrush.com で1,506字、screamingfrog で1,036字、techradar で3,364字

**ボイラープレート除去が先に行われ、その結果の先頭200字が切られている。**

ただし除去に失敗する例がある（Nobilistaトップ、Peec AI比較ページ）。失敗した2ページは
どちらも `main` も `article` も持っていなかった。成功した4ページのうち3ページは `main` あり
（ahrefs.com は `main` 無しでも成功しているので、`main` の有無だけが決め手ではない。n=6の観察）。

実務上の含意：最適化の対象は meta description ではなく **本文の先頭 約200字**。
加えて、本文の範囲（`main` / `article`）を宣言して抽出の手がかりを増やす。
