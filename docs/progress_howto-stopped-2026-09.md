# HOW TO生成が3日連続で止まっていた件の修正と、方針の再確認（2026-09-19）

「SEOがダメ」の実体を調べたら、施策ではなく生成パイプラインが止まっていた。その修正と、
9/13に決めた方針（`docs/progress_gsc-2026-09.md`）が実行できていたかの確認。

## 1. 何が起きていたか（実測）

`content/howto-topics.csv` の履歴（`git log -- content/howto-topics.csv`）で確認した。

| 日付 | コミット | 起きたこと |
|---|---|---|
| 09-16 | afd6163 | 「SEOに関係するボットの一覧と見分け方」を記事化（id:86）。残り3件は「採用」のまま |
| 09-17 | 39616d7 | インデックス登録されない原因 → 生成失敗、「候補」へ差し戻し |
| 09-18 | c4059c9 | canonical → 生成失敗、「候補」へ差し戻し |
| 09-19 | aedf663 | 検索トラフィック減の切り分け → 生成失敗、「候補」へ差し戻し |

3件とも同じエラー。`生成失敗: 草稿の本文が0字で改稿できない: frontmatter missing title/date`

**ワークフローは3日とも緑で終わっていた**。`generate-howto.ts` は生成失敗を `exit 0` で終えるので
（メモを残した csv を commit するため。これ自体は正しい）、失敗が通知に出る経路が無かった。

## 2. 原因

`scripts/article.ts` の `extractText()` が**最後のtextブロックをそのまま記事本文として扱っていた**。
csv の note に残っていた生出力から、崩れ方は2種類あった。

1. **前置きが frontmatter の前に付く**（09-18 canonical）
   `すべて確認できました。最終版を出力します。 --- title: "canonical…`
   gray-matter は先頭の `---` しか見ないので frontmatter を読み落とす。
2. **最後のブロックが独り言だけで、MDXは手前のブロックにある**（09-17・09-19）
   `Now fix the remaining long sentences.` / `Now let's view the whole final file and do final validation checks.`

どちらも frontmatter は生成されていた。**記事は書けていたのに取り出しに失敗して捨てていた**（API代は毎回発生していた）。

## 3. 打った手

- [x] 1. `src/lib/mdxResponse.ts` に `extractMdx()` を切り出す（純関数）。
      frontmatter（title と date を持つ `---` ブロック）を持つ**最後の**textブロックを選び、その `---` から先を返す。
      前置きの水平線 `---` を frontmatter と誤認しないよう、候補を順に試して title/date の有無で判定する。
      1つも見つからなければ最後の非空ブロックを返す（`FETCH_FAILED`・空応答の判定は後段に残す）。
- [x] 2. `src/lib/mdxResponse.test.ts` で上の2種類の崩れ方を固定（8件）。実際の生出力をそのままテストの入力にした。
- [x] 3. `scripts/article.ts` の `extractText()` を `extractMdx()` 経由にする。
- [x] 4. `scripts/generate-howto.ts` が失敗件数を `$GITHUB_OUTPUT` に書き、
      **pushが済んだあとのステップ**（`daily-articles.yml` の「HOW TO生成の失敗を検知」）が赤にしてLINE通知を鳴らす。
      生成ステップ自体を落とすと、原因を書いた csv が commit される前にジョブが止まるので順番を変えない。
- [x] 5. 差し戻された3件を「採用」に戻し、note を元の採用理由に復元する（生成失敗のメモで上書きされていた）。
- [x] 6. id:86 を公開（`draft: false`）。`host` コマンドの実行例がコードフェンス無しで本文に置かれ、
      ただの段落として描画される状態だったので囲んだ。

**通しの確認（2026-09-20 00:00 UTC の定期実行、run #31）**: 修正後の初回で記事が1本生成された。

- `content/articles/0087-2026-09-20-4zj261.mdx`（本文4,956字・必須見出し4つ・`draft: true`）
- 「検索トラフィックが減ったときの原因の切り分け」が「公開」に変わり、`articleId: 87` が入った
- ワークフローは success。追加した「HOW TO生成の失敗を検知」ステップは発火していない
- 残り2件（インデックス登録されない原因 / canonical）は「採用」のまま。1日1本の設計どおりで、翌日・翌々日に回る

なお cron は `0 22 * * *`（22:00 UTC）だが、GitHubのスケジュール遅延で**実測は 23:56〜00:10 UTC**に走っている。
