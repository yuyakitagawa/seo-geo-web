# 進捗: 修正提案書の型を教科書へ組み込む

既存サイトを点検して出た指摘を「優先度つきの修正提案書」にまとめる型を、
新しいレッスンを増やさずに既存レッスンへ分散して組み込む。
元になったのは、実在企業のサイトに対する修正提案書（社外向け・非公開）。
**社名・そのサイト固有の観測事実は教科書に持ち込まず、型だけを抽象化して書いた。**

## どこに入れたか（重複を作らないための割り当て）
| 提案書の中身 | 入れた先 | 既存との関係 |
| --- | --- | --- |
| 優先度の付け方・1件の書式・フェーズ割り | `/learn#plan`「直す候補が大量に出たときの並べ方」 | 90日の着手順を持つ節の続き。新規サイト向けの流れに、既存サイト向けの並べ替えを足した |
| 冒頭の要点ボックス（期限・費用・所要時間） | レッスン06 `#shape` | 既存は「セクションごとの直答」。ページ単位の要点先出しは別物として h3 で追加 |
| 数値を画像・PDFで出さない | レッスン06 `#shape` | 抜き出される単位＝パッセージという既存の説明から導く（新しい外部の主張を足さない） |
| `/index.html` の重複・ホストごとの確認 | レッスン09 `#host` | パラメータ違いはレッスン05が持つので、そちらへのリンクだけ置いた |
| 旧URLの棚卸し（301・残す・404） | レッスン13 `#migration` | 既存は「移転の手順」。移転していないサイトに溜まる旧URLを h3 で追加 |
| 複数ホストを1エンティティに束ねる | レッスン14 `#entity` | 既存は表記ゆれの束ね。ホストをまたぐ宣言を段落で追加し、レッスン09と相互リンク |
| 公式ファクトページ（数値＋適用条件＋改定日） | レッスン14 `#data` | 既存は「自分で作る独自データ」。自社しか一次情報を持たない数値を h3 で追加 |
| 構造化データ（FAQPage / HowTo / BreadcrumbList） | 追加しない | レッスン05 `#structured` の表に既にある |
| llms.txt・AIクローラーの許可方針 | 追加しない | レッスン10 が既に持つ（`#robots` と「やらなくていいこと」） |
| AI回答の引用元の定点観測 | 追加しない | レッスン14 `#measure` と レッスン11 `#ai` が既に持つ |

## 決めたこと
- **新しいレッスンは作らない**。教科書は14レッスンのまま。提案書は1章に値する分量があるが、
  中身の8割は既存レッスンの話題で、別章にすると同じ手順が2か所に出る（README の「同じ手順を両方に書かない」に反する）。
- **整合性の要点は「まとめて直す」と「1つずつ測る」の切り分け**。提案書はP1をまとめて入れる前提だが、
  レッスン11は「同時に複数の施策を打たない」と書いている。矛盾に見えるので `/learn#plan` 側で明示的に切り分けた
  （検証指標が観測で直接確認できる修正＝まとめてよい／表示回数で測る施策＝1つずつ4週間）。
- **優先度の基準は「影響の大きさ」ではなく「他の修正の前提か」**。元の提案書のP1/P2/P3をそのまま持ち込むと
  根拠のない重み付けになるため、3段の意味を前提関係で定義し直した。
- 新しい外部の主張は足していない。出典は各レッスンが既に持っているものだけで、
  Googleが書いていない整理（3段の分け方・1件6項目・要点ボックスの項目・旧URLの3分類）はキャプションに明記した。
