# 進捗: 候補に入った後、何が引用を決めるのか（クレジットカードで実測）

Suganthan Mohanadasan の調査
（[ChatGPT Already Knows Who's In The Running Before It Searches](https://suganthan.com/blog/chatgpt-decides-before-it-searches/)）は
AI検索の可視性を2つのゲームに分けている。

- **ゲーム1**: 検索する前の候補リストに名前が入るか（記事61の調査1・記事71で扱い済み）
- **ゲーム2**: 候補に入った後、引用を取れるか ← **この作業で扱うのはこちら**

向こうの数字（英語・ドバイの1アカウント・2026年7月24〜25日・57会話）は次のとおり。

| 切り口 | 結果 |
|---|---|
| 取得3,554ページ → 引用110 | 3.1% |
| グループ内の順位 | 1位5.2% / 2位4.6% / 3位2.4% / 4位1.7% / 5位0.6% / 6位以降0.3% |
| 同一ドメインが同じグループに入れた枚数 | 1枚4.0% / 2枚6.2% / 3〜4枚約4.3% / 5枚1.9% / 6枚以上1.7% |
| 関連度 | 引用ページは候補の上位5%だが、最も一致だったのは20%だけ |

**日本語の質問での再現性は誰も出していない。** そこを自分のログで埋める。

## 題材はクレジットカード

記事30（`gpt-5-6`・2026-08-31・候補36URL→引用4）と
記事75（Sol `gpt-5-6-thinking`・2026-09-10・候補78URL→引用5）が同じカテゴリなので、
**過去の観測とそのまま並べられる**。公式ドメインと比較メディアが両方候補に入るカテゴリでもある
（記事30では比較メディア14件が候補に入って引用ゼロだった）。

## 計測条件

`docs/progress_chatgpt-probe.md` と同じにする。

- ログイン状態、デスクトップWeb、新規チャット（一時チャットは使わない）
- メモリ：無効（設定 → パーソナライズ → メモリを有効にする → OFF）
- カスタム指示：全項目を空
- モデルは1セット内で固定し、ファイル名と下の表に記録する
- 会話APIのレスポンスJSONを1会話1ファイルで `data/fanout/<プローブ>-<反復>.json` に保存（例 `K1-1.json`）

## プローブ5本

| ID | 質問 | ねらい |
|---|---|---|
| K1 | `クレジットカードのおすすめを教えて` | 記事30・75と同一文。過去の観測と接続する |
| K2 | `年会費無料のクレジットカードでおすすめは？` | 条件1つ |
| K3 | `還元率1%以上・年会費無料・ネット通販でよく使う人向けのクレジットカードを3つ挙げて` | 条件3つ。候補が入れ替わるか（記事71の型） |
| K4 | `クレジットカードの比較ランキングで人気なのはどれ？` | 比較メディアが候補に入るか。入ったうえで引用されるか |
| K5 | `クレジットカードの年会費が高くて見直したい` | 不満の言い方。商品名を出していないのに候補が出るか |

**5本 × 4反復 = 20会話。** 記事30・75の実績（1会話あたり候補36〜78件）から、**1,000〜1,500行**になる見込み。
`scripts/fanout-report.ts` は1,000行に届くまで率を出さない（実数のまま出して警告する）。

反復は**2日に分ける**（1日2反復）。同日にまとめて取ると揺れと差が分離できない
（記事33で引いた「Don't Measure Once」arXiv:2604.07585 と、記事71で実際に日をまたいで入れ替わった件）。

## 手順

- [ ] 1. 計測条件を設定する（メモリOFF・カスタム指示を空）。設定画面を確認してから始める
- [ ] 2. **まず1会話だけ取る**（K1-1）。DevTools → Network → 質問を投げ、**回答が完走してから** conversation のレスポンスを保存
- [ ] 3. `npm run fanout` を回し、出力の「グループの単位」を見る
      - 1ドメインだけのグループが9割超 → ドメイン単位（Suganthanの読み）
      - そうでない → クエリ単位（記事30の読み）
      - **ここで順位の表の意味が変わる。確定してから残りを取る**
- [ ] 4. 1日目：5プローブ × 2反復（10会話）
- [ ] 5. 2日目：同じ5プローブ × 2反復（10会話）。モデル表示が変わっていたら記録する
- [ ] 6. `npm run fanout` で集計。`data/fanout/rows.csv` を確認する
- [ ] 7. 記事化（独自記事・手書き）。`content/howto-topics.csv` に候補として入れてある
- [ ] 8. `npm run translate:en -- <id>`（独自記事には英語版が必須）

## 記事に書くときの線引き

- **1,000行に届かないうちは率を書かない。**「この観測ではこうだった」の実数で書く
- 1アカウント・日本語・クレジットカードの観測であることを冒頭に置く（Suganthanも同じ断りを入れている）
- Suganthanの数字と並べるときは、**向こうが英語・ドバイ・別カテゴリ**であることを必ず添える
- グループの単位がクエリ単位だった場合、「グループ内順位」はSuganthanの言う順位と別物になる。
  そのときは同じ名前で呼ばず、何を数えたかを書く
- 既存記事との関係：記事30（候補→引用の脱落）、記事70（スニペットの先頭200字）、
  記事71（条件で候補が入れ替わる）、記事75（検索の3段階）。**重複する結論を書き直さない**
