## 結論

Search Consoleは、インデックス作成・検索パフォーマンス・URL検査・生成AIの4レポートを見れば足ります。

登録の作業は、プロパティの追加と所有権の確認だけです。Googleは公式ドキュメントで、確認は月1回程度でよいと案内しています。毎日開いて数字を眺める道具ではありません。速度とクロールの画面は、サイトが大きくなってから見ます。

Search Consoleは、Google検索での自サイトの状態を確認できるGoogleの無料ツールです。どのクエリで何回表示されたか、どのページがインデックスに登録されたかが分かります。

## Search Consoleで分かること、分からないこと

分かるのはGoogle検索の中で起きたことだけです。サイトに来たあとの回遊やコンバージョンは、アクセス解析（Google アナリティクスなど）の担当範囲になります。

ChatGPTやPerplexityからの流入も、Search Consoleには出ません。これらは別の会社のサービスだからです。参照元ドメインでアクセス解析側から見ます。

一方、GoogleのAIによる概要とAIモードでの表示は、Search Consoleに含まれます。2026年6月に専用のレポートが追加されました。詳しくは手順5で扱います。

### 1. プロパティを追加して所有権を確認する

プロパティとは、Search Consoleが数値を集計する単位のことです。種類が2つあり、ここを間違えると数値が分散します。

ドメイン名の設定画面（レジストラやDNSサービス）に入れるなら、ドメインプロパティを選んでください。www有無で数値が割れる事故を防げます。

DNSレコードを触れない場合は、URLプレフィックスプロパティを作ります。サイト全体を見たいときは、正規のURLの形（多くは `https://www.example.com/`）で登録します。

### 2. サイトマップを送信する

サイトマップは、サイト内のURLを一覧にしたファイルです。多くのCMSは自動生成し、`/sitemap.xml` に置きます。

Googleは、サイトマップが不要な条件を明記しています。500ページ以下で、トップページからのリンクをたどればすべてのページに到達できるサイトです。

送信は、Search Consoleのサイトマップ画面にURLを貼るだけです。ステータスが「成功しました」になり、検出されたURL数が公開ページ数とおおむね一致していれば完了です。

ここで注意が1つあります。公式ヘルプは、検出されたURLがクロールやインデックス登録をされるとは限らないと書いています。サイトマップは通知であって、登録の約束ではありません。

### 3. ページのインデックス作成レポートで「未登録」の内訳を見る

このレポートは、Googleがサイトのページを登録したかどうかを一覧にします。見るのは「未登録」の件数ではなく、その理由です。

タグ一覧やパラメータ違いのURLも未登録に入ります。件数が多いこと自体は問題になりません。

| 理由（公式の表記） | 意味 | 対処 |
| --- | --- | --- |
| クロール済み - インデックス未登録 | 読まれたが登録されなかった | 内容の薄いページか確認し、統合か加筆を検討する |
| 検出 - インデックス未登録 | まだ読まれていない | 待つ。再リクエストは不要 |
| 重複しています。ユーザーにより正規ページとして選択されていません | 似たページがあり正規指定がない | canonicalで正規ページを明示する |
| noindex タグによって除外されました | noindexの指定がある | 登録したいページなら指定を外す |
| ページにリダイレクトがあります | 別URLへ転送している | 転送先の登録状況を見る |

例えば商品ページが1,200点あるECサイトで、未登録の大半が「重複しています。ユーザーにより正規ページとして選択されていません」だとします。この場合はサイズ違い・色違いのURLが原因なので、代表ページへcanonicalを向けます。

個別のページを確定させたいときは、画面上部のURL検査ツールを使います。ここでは「Googleが選択した正規URL」が確認できます。自分が指定したcanonicalが採用されているかを見られる場所です。

URL検査ツールにはインデックス登録のリクエスト機能もあります。ただし公式ヘルプは、リクエストしてもGoogleのインデックスに表示されるとは限らないと明記しています。1日あたりの上限もあるため、公開・更新した重要なページだけに使います。

### 4. 検索パフォーマンスレポートで4つの数字を読む

このレポートには4つの指標が並びます。定義は公式ヘルプのとおりです。

- クリック数: ユーザーが検索結果からサイトをクリックした回数
- 表示回数: サイトが検索結果に表示された回数
- CTR: クリック数を表示回数で割った値
- 平均掲載順位: 検索結果でのサイトの最上位の結果の平均

既定の期間は過去3か月です。全体の推移だけを見ても打ち消し合いが起きるため、ページ別とクエリ別のタブを必ず開きます。

例えば全40ページのBtoBサイトで、表示回数が月800回に対しクリックが12回だとします。表示は取れているので、次に直すのは記事の量ではなく、タイトルと説明文（ディスクリプション）です。

グラフと表の右上にはエクスポートボタンがあります。分析を続けるならCSVに出しておくと扱いやすくなります。

### 5. 生成AIパフォーマンスレポートでAI検索での露出を見る

2026年6月、Googleは生成AIパフォーマンスレポートを発表しました。公式ヘルプは、2026年8月31日に全世界で使えるようになったと案内しています。ただし、すべてのプロパティですぐ使えるとは限りません。

対象はAIによる概要とAIモードです。Search Labsの試験運用版のデータは含まれません。

指標は表示回数だけで、クリック数はありません。表示回数は、生成AI機能の中で自サイトへのリンクが表示された回数を指します。ディメンションはページ・国・日付・デバイスの4つです。

このデータは新しく取れるようになったものではありません。元は検索パフォーマンスレポート（検索結果）のウェブ検索タイプに含まれていた分を、切り出して見せる画面です。

## 数字を読み違えないための3つの決まり

Search Consoleの数字は、そのまま足し算できません。3つだけ覚えておけば誤読を避けられます。

1つ目は匿名化クエリです。ユーザーのプライバシー保護のため、一部のクエリはレポートから除外されます。この分はクエリフィルタをかけない限りグラフの合計には含まれるため、クエリ表の合計とグラフの合計は一致しません。

2つ目は行の制限です。公式ヘルプは、内部的な制限により最も重要なデータ行のみが保存・表示されると説明しています。表に出ていないクエリやページが存在します。

3つ目は平均掲載順位です。これはサイトの最上位の結果の平均であり、2位と8位に同時に表示された場合は2位側が使われます。順位が「上がった」ように見えても、下位のページが消えただけのことがあります。

## 4つの次に見る画面：速度とクロール

速度とクロールを最初の4つに入れていないのは、優先順位が下だからです。Googleは、検索は常に最も関連性の高いコンテンツを表示するよう設計されていると書いています。ページエクスペリエンスが平均を下回るコンテンツも、その対象です。

ただしサイトが大きくなると、どちらも効いてきます。見る場所と、見なくてよい条件を示します。

### ウェブに関する主な指標（速度）

このレポートは、実際にサイトを訪れたChromeユーザーのデータ（CrUXレポート）にもとづきます。自分のパソコンで測った速度ではありません。

指標は3つあります（[用語集](/glossary)）。LCPは最も大きな要素が表示されるまでの時間、INPは操作への反応の遅さ、CLSは表示のずれの量です。それぞれ「良好」のしきい値が決まっています。

判定はURL単位ではなく、体験が似たページのグループ単位で行われます。しきい値のデータが足りないURLグループは、そもそもレポートに出ません。公開したばかりのサイトで画面が空なのは、この理由です。

直したあとは「トラッキングを開始」を押します。28日間のモニタリングが始まり、修正できたかを確認できます。

判断基準は公式に書かれています。Core Web Vitalsレポートで良い結果が出ても、上位表示は保証されません。サードパーティのツールでも同じです。内容が弱いページの速度だけを直しても、順位は動きません。

### クロールの統計情報

場所は、左メニューの「設定」の中です。ルートレベルのプロパティ（ドメインプロパティ、またはルートのURLプレフィックス）でしか使えません。

公式ヘルプは、このレポートを上級ユーザー向けとしています。ページ数が1,000未満のサイトでは使う必要はない、と明記されています。

| 見る場所 | 何が分かるか | 異常の見分け方 |
| --- | --- | --- |
| ホストのステータス | robots.txtの取得・DNSの解決・サーバー接続 | 3つとも問題なしが正常 |
| クロール レスポンス | 200・301・404などの内訳 | 5xxや429が増えていないか |
| ファイル形式 | HTML・画像・JavaScript・CSSなど | 画像やJSがクロールを占めていないか |
| クロールの目的 | 「検出」（新規）と「更新」（再訪）の比率 | 新規ページが検出されているか |
| Googlebot の種類 | スマートフォン・パソコン・画像など | 主役がスマートフォンになっているか |

データは過去90日分です。合計クロールリクエスト数・合計ダウンロードサイズ・平均レスポンス時間も同じ画面に出ます。

クロールバジェット（Googleがそのサイトに割くクロールの量）を気にすべき規模も、公式が示しています。重複のないページが100万以上で週1回更新されるサイト、または1万以上で毎日更新されるサイトです。

クロール頻度の上限は、サイトの応答が遅くなったときに下がります。5xxエラーや429を返したときも同じです。

無駄を減らす方法として、公式は次を挙げています。

- 重複コンテンツを解消する
- 削除したページには404か410を返す
- soft 404（内容が無いのに200を返すページ）を無くす
- サイトマップを最新の状態に保つ
- リダイレクトチェーンを削る

例えば商品ページが10万点あるECサイトで、クロールの目的が「更新」に偏っているとします。新規商品が検出されていない可能性があるため、サイトマップの更新日時と内部リンクを先に見ます。

## よくある質問

### Search Consoleに登録すると検索順位は上がりますか

Search Consoleへの登録そのものが検索順位を上げることはありません。Search Consoleは自サイトの状態を確認して問題を見つけるための計測ツールです。順位はページの内容とサイトの状態で決まります。

### インデックス登録をリクエストすれば必ず検索結果に載りますか

載るとは限りません。URL検査ツールの公式ヘルプは、リクエストしても登録が保証されないと明記しています。リクエストには1日あたりの上限もあるため、公開・更新した重要なページに絞って使います。

### クエリ表の合計と、グラフの合計が一致しないのはなぜですか

匿名化クエリと行の制限があるためです。プライバシー保護のため、一部のクエリはレポートから除外されます。その分はクエリフィルタをかけない限り、グラフの合計にだけ含まれます。加えて、内部的な制限により表には最も重要な行だけが表示されます。

### AI検索での露出はSearch Consoleのどこで見られますか

生成AIパフォーマンスレポート（検索）で見られます。AIによる概要とAIモードでの表示回数が、ページ・国・日付・デバイス別に確認できます。クリック数は含まれず、Search Labsの試験運用版のデータも対象外です。

### サイトの表示速度はSearch Consoleのどこで見られますか

「ウェブに関する主な指標」レポートで見られます。元は、実際にサイトを訪れたChromeユーザーのデータ（CrUXレポート）です。LCP・INP・CLSの3指標を「良好」「改善が必要」「低速」に分けて表示します。自分のパソコンで測った速度とは別の数字です。

### 速度を直せば検索順位は上がりますか

上がるとは限りません。Googleは、Core Web Vitalsレポートで良い結果が出ても上位表示は保証されないと明記しています。ページエクスペリエンスに単一のシグナルはなく、関連性の高いコンテンツが優先されます。

### クロールの統計情報は誰が見るべきですか

公式ヘルプはこのレポートを上級ユーザー向けとしています。ページ数が1,000未満のサイトでは使う必要はない、という案内です。対象は大規模サイトだけです。重複のないページが100万以上で週1回更新、または1万以上で毎日更新されるサイトを指します。

### Search Consoleは毎日確認する必要がありますか

必要ありません。Googleは公式ドキュメントで、月1回程度、またはサイトの内容を変更したときの確認を挙げています。重大な問題が起きたときはメールで通知が届きます。
