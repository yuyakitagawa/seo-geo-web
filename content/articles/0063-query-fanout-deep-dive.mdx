## 結論

fan-outクエリはGoogleが公式に定義した用語で、第三者調査では1問が平均9〜11本に分かれます。推測や業界の造語ではありません。Googleは自社のドキュメントで語を定義し、具体例まで載せています。

分解の本数は質問の複雑さで大きく変わります。当サイトが取得したChatGPTの実ログでは3本でしたが、AhrefsはAI Modeで最大28本の観測を紹介しています。

ページ側でやることは、キーワードを増やすことではありません。**1つのページの中で、隣り合う複数の意図に見出し単位で答える**ことです。

## Googleが公式に定義している言葉である

まず確認したいのは、fan-outが観測ベースの俗語ではないという点です。Googleは生成AI機能向けの公式ガイドで、用語として定義しています。

<FigureQuote
  text="A set of concurrent, related queries generated by the model to request more information and fetch additional relevant search results to address the user's query."
  source="Google Search Central「Google Search's guide to AI features and your website」"
/>

日本語にすると「ユーザーの質問に答えるため、モデルが同時に生成する関連クエリの集まり」です。同時に投げること、元の質問に答えるために追加情報を取りに行くこと、この2点が定義に入っています。

Googleが載せている例も具体的です。「雑草だらけの芝を直す方法」という質問から、「芝に最適な除草剤」「薬剤を使わない雑草の除去」「芝の雑草を予防する方法」といった検索語が作られます。

2025年3月のAI Mode発表でも、Googleは同じ技術名を使いました。サブトピックと複数のデータソースをまたいで、関連する検索を同時に発行する技術だと説明しています。発表時点では米国のGoogle Labsでの試験提供で、Gemini 2.0のカスタム版が使われていました。

## 1問が何本に分かれるのか

Ahrefsは、Seer InteractiveとNectivの調査として、1つのプロンプトあたり平均9〜11本という数字を紹介しています。分布も出ています。

全体の59%は5〜11本の検索を実行し、24%は12〜19本でした。最大では28本が観測されています。

同じAhrefsの記事では、赤いスマホケースを買う場面の比較が出てきます。AI Modeが5〜11本のところ、ChatGPTの深い調査モードは420本の検索を実行したという例です。

一方で、当サイトが[ChatGPTの会話JSONを解析した記事](/articles/30)では、fan-outクエリは3本でした。「おすすめのクレジットカードを教えて」という、条件のない1文の質問です。

ここから読み取れる判断基準は単純です。**条件・比較軸・時期が多い質問ほど本数が増える**ということです。自社の読者が投げる質問がどちらに寄るかで、対策の優先度は変わります。

- 本数が増えやすい: 「従業員20人の会社に合う勤怠管理システムを、料金とサポートで比べたい」
- 本数が増えにくい: 「勤怠管理システムとは」

前者を狙うページなら、料金・サポート・従業員規模の3つの意図に、同じページの中で答える必要があります。

つまり、1本のサブクエリで1位を取るより、**隣接する3〜4本のサブクエリで拾われるほうが有利**になりえます。ページを細かく分けて1意図ずつ狙う設計と、相性が悪いということです。

## どんな種類のサブクエリが作られるか

Ahrefsは、Googleの特許出願の分析をもとに、サブクエリの型を6つに分けています。

| 型 | 何をするか | 例えば「クラウド会計ソフトの選び方」なら |
| --- | --- | --- |
| 関連トピック | 文脈を補う話題を足す | 電子帳簿保存法への対応 |
| 暗黙の質問 | 明示されていない懸念を拾う | 乗り換え時のデータ移行 |
| 比較 | 選択肢を並べて評価する | 主要ソフトの料金比較 |
| 新しさ | 時期に敏感な情報を優先する | 2026年の制度変更 |
| 言い換え | 同じ意図の別の表現で引く | 会計ソフト おすすめ 法人 |
| 文脈による変化 | 履歴や状況で変わる | 個人事業主向けか法人向けか |

Search Engine Landは、これを別の切り口で8つに分けています。言い換え、次に来る質問、より広い範囲、用語の統一、多言語、論理的な帰結、より狭い焦点、曖昧さの解消の8つです。

分類の細部は媒体で違いますが、共通しているのは1点です。**元の質問より狭い問いと、元の質問より広い問いの両方が作られる**ということです。

Search Engine Landは、狭い問いにしか答えていないページは、追加のサブクエリが入ったときに弱いと指摘しています。原文では「正確ではあるが、耐えにくい」という書き方をしています。

## 手順

自分のサイトで確かめるところから始めます。ツールを買う前に、無料でできる範囲があります。

1. 自社カテゴリの質問を5〜10本作る。「〇〇の選び方」「〇〇 比較」「〇〇 乗り換え」のように、条件の多いものを混ぜる
2. ChatGPTやAI Modeで実行し、回答に出てくる小見出し・比較軸・注意点をそのまま書き出す。これがサブクエリの代理指標になる
3. 取得できる環境なら、会話JSONの `search_model_queries` を保存する。手順は[実ログを解析した記事](/articles/30)に置いてある
4. 書き出した意図を1列に並べ、自社ページのH2・H3を隣の列に並べる。表計算ソフトで2列にするだけでよい
5. 対応するH2が無い行を、抜けている意図として印を付ける。3行以上あればページの作り直しを検討する
6. 抜けていた意図をH2として追加し、見出しの直下に2〜3文で結論を書く。比較の意図は表にする
7. 2〜4週間後に同じ質問を実行し、回答内の言及と引用が変わったかを記録する

4番目の作業は、想像以上に効きます。例えば「勤怠管理システム 比較」で作ったページに、料金と機能の表はあるのに、導入時の設定作業に触れた見出しが無い、といった抜けが可視化されます。

もう1つの例です。歯科医院のサイトで「インプラント 費用」のページを作ったとします。AI検索の回答には保証期間・治療期間・分割払いが並ぶのに、ページには費用表しか無いことがあります。

このとき作るべきは新しい記事ではありません。同じページに見出しを足すほうが、複数のサブクエリで拾われる可能性が上がります。

やらなくていい側の4つは、Googleが公式ガイドではっきり否定している内容です。機械可読ファイルやマークダウンを新しく作る必要はない、コンテンツを細かく分割する必要はない、と書かれています。

構造化データについても、生成AI検索のために必須ではなく、追加すべき特別なスキーマも無いと明記されています。構造化データはリッチリザルトなど本来の目的で整備してください。

キーワードの網羅についても同じです。ロングテールの語や表現の揺れを取りこぼしていないか心配する必要はない、というのがGoogleの説明です。

1ページに複数のトピックが載ることも問題になりません。Googleのシステムは1ページ内の複数トピックの機微を理解し、関連する部分を出せるとしています。これがページを分けずに意図を足す根拠になります。

## よくある質問

### fan-outクエリを自分で見ることはできますか

環境によっては見られます。ChatGPTでは会話のJSONに検索語が記録される場合があり、ブラウザの開発者ツールから確認できます。ただし表示仕様は変わるため、取れないときはAI検索の回答に現れる小見出しや比較軸を代理指標として記録してください。

### 1ページにまとめるのと、記事を分けるのはどちらが有利ですか

隣り合う意図であれば、1ページにまとめるほうが有利になりやすいです。統合の段階で、複数の結果リストに繰り返し現れるページが高く評価されると説明されているためです。話題が明確に別なら、無理に1ページへ詰め込む必要はありません。

### 構造化データを足せばfan-outクエリに強くなりますか

なりません。Googleは、生成AI検索のために構造化データは必須ではなく、追加すべき特別なスキーマも無いと明記しています。構造化データはリッチリザルトなど本来の目的で使い、fan-out対策の主役にはしないでください。

### fan-outクエリの本数を増やすことはできますか

サイト側から本数を操作する方法は公開されていません。本数は質問の複雑さで決まり、条件や比較軸が多い質問ほど増えます。増やそうとするのではなく、増えたときに拾われる見出しを用意するほうが再現性があります。
